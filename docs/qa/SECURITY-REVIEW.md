# Security and privacy review — Munazara PWA

Reviewer: independent (fresh context). Date: 2026-11-13. Scope: `src/**`, `index.html`, `public/`, `vite.config.ts`, `src/sw-template.js`, `.github/workflows/*.yml`, built `dist/` (`npx vite build`). No public Nostr relay was contacted (all Playwright WebSockets were intercepted and closed).

## Verdict

**Do not ship as is.** The cryptography itself is sound (AES-256-GCM with HKDF key and fresh IV, ECDSA P-256 with key-bound person ids, debateId inside the signature), the CSP and manual-mode network behaviour hold up, and I found no XSS. But there are two serious problems:

1. **S1 (Critical).** Someone who knows only a debate's **id**, which is printed in clear in every "keyless" update link and in every backup file header, can inject participants and points into a victim's debate. They need no room key. With the same trick they can **permanently brick the whole app** on the victim's device: every debate, on every start. The victim's only way out is to clear the site's data, which destroys all their debates and signing keys.
2. **S2 (Critical).** "Invalid events are ignored, never crash the app" is false. Any correctly *signed* event with a wrong-typed field (e.g. `name: 123`) is stored. After that, `derive()` throws on every load. In relay mode this spreads to every participant with no click needed.

Several further High/Medium issues weaken the "a link holder cannot write as an existing participant" promise and the UI's integrity signals.

Evidence scripts (not committed): `/tmp/claude-0/-home-user-Repo-B/2c4b38f4-586b-54e4-9d12-4e043e5bf074/scratchpad/sec/exploits.test.ts` (vitest, run with `npx vitest run --config <scratchpad>/sec/vitest.config.ts`), `.../sec/craft.mts` (crafts a malicious join link), `.../sec/pw.cjs` (end-to-end Playwright against `vite preview --port 4175`), `.../sec/frame.cjs`.

Areas checked and **not** vulnerable:
- XSS: no `dangerouslySetInnerHTML`. Every `href` uses `debateHref` with `encodeURIComponent`. `dir` is always the literal `"auto"`. `meta.ref` is only used as a lookup key. Names and text render as text nodes.
- Prototype pollution: `JSON.parse` `__proto__` stays an own data key, and object spread does not pollute.
- Deep trees: a 20 000-deep `counter` chain derives fine (memoised in parent-first order; `pathTo` is iterative).
- Frame guard: the app does not render inside a cross-origin iframe, with or without a sandbox (`frame.cjs`: `#app` empty).
- SW: caches only same-origin GETs, and Cache API keys exclude fragments.
- Error toasts: they show exception messages only, never key material.
- The secret is removed from the address bar after a link is handled, by `history.replaceState`.

## Claims verified

| Claim | Result | Evidence |
|---|---|---|
| AES-256-GCM, key via HKDF from 32-byte room secret, fresh 96-bit IV per payload | **Verified** | `crypto.ts:28-57`: HKDF-SHA-256, salt `munazara`, info `munazara/v1/enc`, `randomBytes(12)` per `sealJSON`. `parseLink` enforces a 32-byte secret. |
| Room secret lives only in the URL fragment and IndexedDB | **Partly** | True for code paths: no logging, never in requests. But the secret's *binding* to the debate is not enforced (S1), so knowing the id alone is enough to write into the debate. The secret is also in WhatsApp and browser history, which the UI discloses. |
| Update links and backups carry ciphertext only, never the room key | **Partly** | No key: verified (`links.ts:49-52,67-72`). But they carry the debateId in clear, which enables S1, and the accompanying share text and file name carry the plaintext title (S8). |
| Identity links carry the signing key encrypted with the room key | **Verified**, but import is unsafe (S3) | `links.ts:56-58`; `service.ts:250-260`. |
| Every event is signed with ECDSA P-256 | **Verified** | `emit` signs every local event; `canonical` covers all fields, including `debateId` and `at`. |
| personId = first 16 bytes of SHA-256(raw pub); id cannot be claimed with another key | **Verified** | `crypto.ts:81-84,133`. But display-name impersonation via a backdated join works (S5), and event-id squatting works (S4). |
| Unverifiable events are rejected on ingest | **Verified** (all paths) | Every external path goes through `ingest → verifyBatch`: join link, update link, backup, plain JSON import, relay. Only `emit` (locally signed) bypasses it. However, a malformed `pub` aborts the whole batch (S6). |
| debateId bound into the signature (no cross-debate replay) | **Verified** | `canonical` includes `debateId`; `ingest` filters `e.debateId === debateId`. |
| Deterministic reducer; invalid events ignored, never crash | **Refuted** | S2: a typed-wrong signed event crashes `derive` and blanks the app on every start. Determinism with respect to arrival order holds, but `at` is attacker-chosen (S5). |
| Relay: kind 4333, HKDF room tag, per-device random Nostr key, so no cross-device deletion | **Verified** | `nostr.ts:7,13-21`; `engine.ts:41`; the tag comes from HKDF info `munazara/v1/tag`; `nostrSk` is random per device and debate. |
| Manual mode makes zero non-origin requests | **Verified** | Playwright, manual-mode debate plus link handling: `non-origin requests: []`, `websockets: []`. Note: relay mode is the default (S10). |
| No analytics, trackers or third-party resources | **Verified** | The built `dist/` contains no external URLs other than XML namespace strings, and fonts are self-hosted. |
| CSP meta first in `<head>`; noindex; no-referrer; frame guard | **Verified** | `dist/index.html`: the CSP meta is the first element (before charset), and `robots noindex,nofollow`, `referrer no-referrer` and `frame-guard.js` (classic script, before the module) are all present.
